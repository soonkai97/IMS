# QA round: edge / accessibility / permissions (main 7fdbbc8, web :4200, api :5209)
Method: own headless Chromium (Playwright, scripts in this folder) because no tab-creation tool was available and the shared Browser tab was in use by another agent; API checks with curl. Screenshots in shots/ (scripts and screenshots stay on the tester's machine, not published). No repo changes. Test data prefixed QA- (products QA-E-*, QA-STALE-*, roles, users qa-edge-*, partners, categories, warehouses QAW1 / "QA W2", ~25 QA-edge drafts/docs). One shared setting (low-stock cool-down) was briefly set to 0 by a validation probe and restored to 24.

## SECURITY (first)
S1 Medium: service worker keeps API master-data answers after sign-out and serves them with no token.
   Steps: sign in as admin, browse /products and /partners, sign out, then from the login page run fetch('http://localhost:5209/api/units') and fetch('/api/products?Active=true&Page=1&PageSize=25') (same URL as one browsed): both return 200 with data; an uncached URL returns 401. Cache group ngsw:/:2:data:master-data (products, categories, units, partners, warehouses, settings; maxAge 12h, strategy performance) is not cleared on sign-out.
   Expected: cleared on sign-out; or not cached cross-user; never served without auth.
S2 Low: access token outlives sign-out and deactivation (stateless JWT, 5 min). Logout then reuse token: 200 on /api/auth/me. Deactivated user's existing token still 200 on stock list. Refresh after logout correctly 401. Second tab stays fully signed in and saved a draft after the first tab signed out (no cross-tab sign-out sync).
S3 Nit: JWT carries internal integer user id (sub / nameidentifier = 1057), against the "public id only" rule.
S4 Info: web origin :4200 sends no CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy (API has them). May just be the dev static server.
Held up: all admin URLs forbidden for staff/clerk/supervisor/owner (UI /forbidden and API 403); every admin POST/PUT/DELETE 403; unauthenticated 401; warehouse scope holds (QAW1 doc: 404 by id, absent from lists, stock, ledger, summary value for WH01-only users; create in other warehouse 400); returnUrl open redirect safe (https://, //, javascript:, backslash); XSS strings (<b>, <script>, <img onerror>) render as text; CSRF header+origin checks on refresh work; evil-origin CORS gets no ACAO; concurrent post x3 = one 200 + two 409; double-click Save = one POST; import rejects fake/oversize/wrong-template files.

## DEFECTS (ranked)
1 Major  Session expiry while editing: Save with an expired session opens "Discard changes?" with no mention of sign-out; header/menu empty. "Keep editing" + Save again returns the same dialog; the only exit is Discard (data lost) which lands on /login?reason=expired. Expected: message "session expired", offer sign-in without losing the draft. (screen: /receipts/new; shots/expired.png). WCAG 3.3.? / 2.2.5 re-authentication.
2 Major  Stale master data from the service worker (cache-first, 12 h) on /api/products*, partners, categories, units, warehouses, settings. Steps: open /products, search QA-STALE (0 rows); create a product with that SKU elsewhere; search again and reload: still 0. With serviceWorkers blocked it is fresh. New products/partners made by someone else are invisible in lists and in the document "Add item" lookup for up to 12 h.
3 Minor  500 on input: POST /api/products with safetyStock 99999999999999999999 returns 500 (should be 400 with a message).
4 Minor  "Keep editing" in the Discard dialog drops focus to <body> (Esc returns it to the link correctly). WCAG 2.4.3.
5 Minor  Browser Back after "Keep editing": the URL is restored but the history position is off by one, so the next Back skips an entry (/receipts/new -> back lands on "/" not /receipts).
6 Minor  List state (page, search, sort, filters) not kept in the URL: open a product from page 2 of a search, press Back: list resets to page 1 and empty search.
7 Minor  At 320 px with 200 % text: Home "Receive/Issue stock" buttons clipped 32 px right; /roles/new "High impact" chip + help text overflow 27 px; bottom nav labels truncate ("H...", "A...") and the badge covers the icon. WCAG 1.4.4 / 1.4.10. (shots/home320z200.png). 360 px and 1440 px with 200 % text are clean.
8 Minor  UI hint says a new user "should change it after signing in" but the web app has no change-password screen (API exists; Account dialog has only language, theme, sign out).
9 Minor  Required-field errors on product and user forms: focus stays on Save and the message is the generic "This field is required." (document editor correctly moves focus to the invalid field). Server errors (duplicate SKU/barcode) are an alert not tied to the field. WCAG 3.3.1 / 3.3.3. Reason box in Reject has no maxlength (server says "The reason is too long").
10 Minor API accepts what the UI blocks or misleads: password of 132 chars gets "must be at least 12 characters" (wrong message); duplicate barcode inside one request gives 409 "data changed, reload"; NUL and tab/newline characters accepted in product names; warehouse code "QA W2" (space) accepted and used in document numbers; partner contact accepted at 5000 chars; product Name input maxlength 256 while the API allows 300; safety stock 1.23456 silently rounded.
Nits: unit cost limited to 2 decimals (qty allows 4) - confirm intended; Supplier is a native select listing every partner incl. 300-char names (does not scale); "Show more" button x61 on Users = 61 tab stops; no offline indicator (only a toast on the failed action; error toast persists, good); More button lacks aria-expanded; duplicate "Save" buttons on role page; qty summary live region announces on every change; blank cells (no dash) for empty Supplier in receipts table; audit log shows "User #<guid>"; 1 000 000 000 units shown without separators in editor summary while table uses commas; 404 inside /roles/<bad> has no alert role while /receipts/<bad> has.
