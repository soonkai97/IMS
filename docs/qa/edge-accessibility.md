# QA report: edge cases, permissions and accessibility

Persona: qa-edge-accessibility. Build: web http://localhost:4200 (service worker active), API http://localhost:5109, throw-away QA database, 2026-10-10. Roles tested: admin, owner, supervisor, staff, clerk (demo users) plus throw-away users `qa_*` created for the test.
Sources read first: `docs/design/mvp-ux.md` (1.2, 6.4, 7.2), `docs/architecture/frontend.md`, `web/README.md`, `docs/security/refresh-cookie.md`, `docs/qa/novice-warehouse-staff.md` (not repeated here, see NV-xx).

## How this was tested (read before trusting the numbers)

- The built-in browser pane has one shared tab (`seed`) that the other QA agents were using live, and no tool to open a tab of my own. To avoid wrecking their sessions I drove my own headless Edge (Chrome DevTools Protocol) against the same URLs: real keyboard events, accessibility tree, viewport emulation (1280, 640, 360, 320, 200% and 400% zoom equivalents), light and dark (`prefers-color-scheme`), a page-side XHR wrapper to simulate 401, 504, 429 and a network error. API checks were done with `fetch`/curl against the same API with each role's token (the pane has no script tool, so "page context" was replaced by direct calls with the same Bearer token and no extra privilege).
- Other agents wrote data at the same time (stock moved, ~1,200 BULK documents and products exist), so absolute counts differ between my runs. The login limiter (20 per minute per address) was hit twice by shared traffic; those results were re-run.
- Not tested: real screen reader speech (I read the accessibility tree instead), soft keyboard, camera scan, real offline mode, `Secure` cookie flag (Development server, by design), TLS and proxy headers (security-engineer's lane).
- Passwords and tokens are not recorded here.

## Summary

Counts: Blocker 0, Major 5, Minor 20, Polish 5 (30 total). The Blocker of this round is NV-01 (save-then-"Discard changes?" and duplicate drafts); I re-confirmed it independently (Save draft on `/receipts/new`: POST 200, dialog appears, Keep editing then Save draft makes a second document) and did not list it again.

Top 5: EA-01 (clerk and staff can edit, submit and cancel other users' documents), EA-02 (owner can approve and reject non-large documents), EA-03 (same page title on every screen, WCAG 2.4.2 Level A), EA-04 (sticky bars take the whole viewport at 400% zoom and cover the focused control, WCAG 1.4.10 and 2.4.11), EA-05 (refresh token still in the JSON body).

## What passed

- Warehouse scope: staff, clerk and supervisor (warehouse 1) could not create (403), read (403), post, cancel or edit a warehouse 2 document; document list, stock list, ledger, stock summary, low stock, movements report and the three Excel exports showed zero warehouse 2 rows for them, while admin and owner saw them. A user with no warehouse sees nothing and gets 403 on create (UI gap: EA-14).
- Quantities (API and form): 0, negative, fractional beyond 4 decimals, 1e12 and above, and `1e300` refused with a field message; 0.0001 and 0.5 accepted; the form shows "This value is too small/too large" (wording: NV-09). Empty lines refused. Unit cost negative refused.
- Duplicate SKU (case-insensitive) 409 "SKU ... already exists."; duplicate barcode 409 with the product named in the sentence; duplicate warehouse code 409; duplicate user name or email 409; blank barcodes dropped.
- Inert display: `<img onerror>`, `<script>`, SKU `<b>`, warehouse name `<script>` with a right-to-left override, emoji and Hebrew/Arabic text all render as text in lists, forms, stock, documents and the account menu at 1280 and 320 px; no script ran (0 JavaScript dialogs, 0 console exceptions). A formula text (`=1+1...`, `=HYPERLINK`) in product and document remarks is written as a string cell in the xlsx exports, not as a formula.
- Concurrency: stale `If-Match` gives 409 and the web shows the stale-document banner (`role="alert"`, Reload) with E4 meaning, nothing saved; parallel double submit and double post: one 200 and one 409; double click on Approve confirm: one POST.
- Session: reload keeps the session (single refresh call); a 401 mid-session refreshes and replays the call; after sign-out in another tab the next call lands on `/login?returnUrl=...&reason=expired` with "Your session expired. Sign in again." and the return URL; reload after sign-out goes to login. No token in localStorage, sessionStorage, IndexedDB or `document.cookie`. Only `ims.language` and a per-user list preference are stored.
- Cookie and CSRF: `ims-refresh` is HttpOnly, SameSite=Strict, Path=/api/auth, 7 days; `Secure` is off only because this is Development over http (documented). Refresh without the `X-Requested-With` header, with a foreign Origin, or without Origin all answer 403; with the header and the allowed Origin 200. Responses carry `Cache-Control: no-store`, `X-Content-Type-Options`, `X-Frame-Options`, a restrictive CSP.
- Import: a `.pdf`, a text file renamed `.xlsx`, and a 6.5 MB file are refused with the spec copy ("Upload an .xlsx file up to 5 MB...", "The file is not a valid .xlsx workbook."); API refuses non-xlsx (400), oversize (400) and missing file (400); clerk gets 403.
- Keyboard: skip link works (first Tab stop, visible, moves focus to `main`); logical order (skip link, account, sidebar, page); every stop measured had a visible focus ring (3px solid blue, 3:1 or better) except the date-input sub-stops (EA-29); `<dialog>` modals trap focus, Esc closes, focus returns to the opener; tabs follow the arrow-key pattern (Mine/All); Enter and Space activate buttons; the confirm dialogs do not pre-focus the destructive button.
- Semantics: `lang="en"`, one `main`, `banner`, labelled navigation landmarks (the pager is a labelled `nav`), tables have captions and `th scope`, no duplicate ids, inputs have visible labels with "(required)", the login form fields have `autocomplete`, no unlabeled controls (the hidden file input on Import is behind a labelled button), status chips have icon plus text, live regions exist before messages ("DEMO-001 added.", "1-25 of 1187").
- Colour contrast (computed, 17 screens, light and dark): no text below 4.5:1; status chips 7.8 to 17.8:1; menu badges 6.6 to 8.3:1; input borders at least 3:1.
- Layout: no horizontal overflow on any screen at 1280, 640 and 320 px in light and dark; phone layout switches to cards with a 63px bottom bar; the sidebar and the bottom bar are never shown together.
- Error handling: 401, 403, 404, 409, 429 and network failure produce a panel or toast with Retry where it applies; the network-failure sentence is the specified one; forbidden routes show the specified E8 page.
- Console and network: the only error in a full admin tour is the expected `401 POST /api/auth/refresh` at start-up (nobody signed in); no failed loads. The service worker registers and caches master-data only.
