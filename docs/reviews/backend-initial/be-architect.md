Ran: `dotnet build src/Ims.Api -c Release -warnaserror` -> 0 warnings, 0 errors. `dotnet test tests/Ims.Architecture.Tests` -> 43/43 pass (note: the suite does not catch findings 6, 12, 22 below). API was not running on :5109, so no endpoint was called; everything else is read from source.

Layering as built: Domain has no package or project references. Application references Domain, Ardalis.Specification and FluentValidation only, and no EF Core, ClosedXML or ASP.NET namespace appears in it. Infrastructure references Application only. Every controller action has an explicit policy except the three anonymous auth actions, and a fallback policy denies everything else. Every by-id document handler calls `EnsureWarehouse`, and every stock, ledger, movement and report read path goes through `IWarehouseScope` or `IDocumentAccess`. DTOs are used for all inputs, so no entity is bound from a request body. Those parts are sound; the findings below are what is left.

## Checked and found sound
- Dependency direction and project references (see top); no `.Result`/`.Wait()`; `IClock` is the only `DateTime.UtcNow`.
- CQRS: no query writes (`GetCurrentUser`, settings, lookups are read-only); pipeline order Logging -> Validation -> handler; commands return a DTO re-read after commit; all handler constructor dependencies are interfaces (the test enforces it).
- Authorization: every action has a policy; fallback policy `RequireAuthenticatedUser`; document handlers check `EnsureWarehouse` before acting; reports, ledger, stock, low-stock, movements and exports all apply scope; the opening-stock import checks scope per row.
- No mass-assignment: all writes take DTO records; header/line/warehouse changes are validated in the aggregate; `UnitCost` on issues is ignored by `CostingPolicy`.
- ProblemDetails: unexpected errors are opaque (`Messages.ServerError` with a reference), concurrency text hides inner exceptions, correlation id is sanitised.
- JWT: issuer, audience, signature, lifetime validated, key min length validated at start-up, ephemeral key only in Development/Testing; refresh tokens stored hashed (SHA-256), rotated, unique index.
- DI: `ValidateScopes` + `ValidateOnBuild`; singletons (`PostingEngine`, strategies, hasher, token service, clock) are stateless; no captive scoped dependency found.
- Export writer stores text as text cells (no formula injection).
