| 2 | Major | `pager.component.ts` `onPageSize` (calls `focusCaption`) | Keyboard: focus Rows per page (closed select), press ArrowDown. Chromium (and Firefox on Windows/Linux) fires `change` at once: value 25 to 50, request `Page=1&PageSize=50`, and the focus jumps to the table caption. A second ArrowDown goes nowhere; reaching 100 means Tabbing back (26 stops at 25 rows). Changing a setting should not move the focus (WCAG 3.2.2), and the select is not disabled by the change, so the A05 reason (focus on a button the new page disables) does not apply. | Do not call `focusCaption()` in `onPageSize`; the live region already announces the new range. Keep it for the page buttons. |
| 3 | Minor | `pager.component.ts` `goTo` | After Next/Previous by keyboard the focus is on the caption, which is `sr-only`: a sighted keyboard user sees no focus, and the pager is 26 Tab stops away (25 rows; about 100 at size 100). Paging through several pages by keyboard needs a long Tab trip each time. Matches A05.1 as written, so a question for ui-ux-designer. | Consider moving focus only when the pressed button becomes disabled (Last, Next on the last page), otherwise leave it on the button. |
| 4 | Minor | `table.component.html:~28` | `aria-haspopup="true"` exposes `hasPopup=menu` (checked with the Chromium accessibility tree), but the popup is a group of checkboxes. `popovertarget` already exposes `expanded=false/true` natively (checked). | Remove `aria-haspopup`. |
| 5 | Minor | `table.component.ts` `onMenuToggle` | Tab past "Show all columns" leaves the menu while the popover stays open (verified: focus on a row button, `:popover-open` true); Esc then no longer returns focus to the Columns button. | Close on `focusout` leaving the popover, or accept and note. |
